## The motivation

Anton's discomfort: the TUI needed the daemon to read the whole file
(`get-context`) to build the display tree, while the query stream plus
the daemon's own action events felt like they should be enough for a
live view. The two questions that drove the discussion:

1. Is the query stream (+ daemon actions) enough for a client to build
   trees, and for the daemon to maintain the context tree?
2. If not, what is the minimum the file stream must add?

Answers, with the evidence that settled them:

- **The file stream is required.** Attachments (token-budget
  reminders, `queued_command`, …) never appear on the query stream
  (0/14 in the capture), yet they are in assistant context: every
  assistant parents on the last attachment, and the CLI's native
  preserved lists include them (docs/specs/context-tree.md 577–585;
  docs/derisk/compact-boundary-injection/FINDINGS.md 462–481). The
  query stream also carries **no `parentUuid`** on shared messages
  (only `parent_tool_use_id`, plus `logical_parent_uuid` on
  `compact_boundary`), so parents must come from the file.
- **The query stream does carry** `claudeCodeVersion`
  (`system/init.claude_code_version`, verified on 2.1.258) and the
  native preserved list (`compact_boundary.compact_metadata
.preserved_messages {anchor_uuid, uuids}` in SDK 0.3.258).
- **Anton does not want a design that depends on a CLI property that
  may go away** (e.g. honoring stamped uuids). So: keep the dual
  stream and the two-sided `MergeState` merge exactly as specified.

Given that, the redesign is about _what the file stream adds to the
socket_, not whether it exists: send what the query stream lacks, and
for entries the query stream already carried, send only the structure.

## The decisions

Each is now in the spec's stable section; the pointer says where.

1. **Emit `sessionEntry` immediately on file observation.** I proposed
   emitting at merge resolution; Anton overruled: clients fold the same
   `MergeState` and may render before resolution; delaying would only
   add latency. (Agent events comment; Non-goals.)

2. **Two wire shapes, chosen by the classification table.** A
   session-only entry (`excludedFromQuery` true: attachments, prompts,
   caveat/`<command-name>`, hook summaries, uuid-less rows) goes out
   **intact** — attachments whole; a client slims them for display if
   it wants. A shared entry (assistant, tool-result/summary/stdout
   `user`, `compact_boundary`, `local_command`) goes out as
   **`structuralEntry(entry)`**: every string at a `PAYLOAD_PATHS` leaf
   replaced by `""`, everything else JSON-equal to the file. (Agent
   events; Structural projection; criterion 6.)

   Why "structural" and not "uuid + parentUuid": the builders read more
   than links. `ToolGroup` (context-tree) reads `message.content[]`
   block `type`/`id`/`tool_use_id`; `lastAssistantOn` and
   `isFinalAssistantEntry` read `message.usage`/`model`/`message.id`;
   the boundary placement reads `compactMetadata`. The former
   `SLIM_PATHS` allowlist already named exactly the payload leaves, so
   the projection is that walk with the limit removed — rename, not
   new machinery. This refinement (keeping the skeleton, not just
   uuid/parentUuid) goes beyond what Anton said in discussion ("drop
   message/content"); it is written into the spec and Anton confirmed
   it in review.

3. **Slimming is gone.** `SLIM_STRING_LIMIT`, `slimEntry`,
   `SlimProjection`, `truncated` (on events, `SessionSnapshot`,
   `ContextSlice`), `EntryPayload`, the hub's full/slim sink sets,
   `subscribe`'s `entryPayload`, `payload: "slim"`, and
   `SessionTracker.entries` are deleted; `slim.ts` becomes
   `structural.ts` exporting `PAYLOAD_PATHS` + `structuralEntry`. There
   is no truncation anywhere and no refetch-on-expand in the TUI.
   (Deleted; Event hub; Wire.)

4. **Daemon retains no entries.** Anton asked whether the daemon needs
   `byUuid` values at all after sending an entry. Answer: no. An entry
   is pushed into the trees **on observation** (not on resolution, as
   round 2 had said — structure is a function of file order, so
   resolution can only delay the push; what resolution guards, an
   unconfirmed leaf, is the fold's `pendingLeaf`/`treeLeaf` job; and a
   set-context boundary is a shared class whose push would otherwise
   wait for the query restart). The tracker deletes an entry from the
   builders' `byUuid` once every dependent has consumed its node (rows
   deferred behind an absent anchor stay until then), and
   `ContextTreeBuilder` records `{usage, model}` per assistant node at
   push so `lastAssistantOn` reads no entries — a small phase-1 builder
   change, done in step 1b. Residency = `SessionTracker.index` (uuid →
   range + class; serves the dedup site and set-context existence
   checks) + trees + deferred rows. Anton: agreed. (Session tracker;
   Rolling builders; Cost.)

5. **Trees are a function of the entry stream.** Daemon and client run
   the same builders over the same `sessionEntry` sequence; since
   `compactMetadata` and the skeleton ride intact, the live tree
   structure equals what a restart rebuilds from the file. The TUI
   never calls `get-context` for `/tree`. (Problem "Wanted"; criterion
   7; Data flow 6.)

6. **Client-side model.** Anton suggested a union-typed `byUuid`
   (SDK message | entry). The spec says instead: `byUuid: Map<UUID,
SessionEntry>` (complete from history, structural or intact from
   live events) feeding the builders unchanged, plus a separate
   `Map<UUID, SDKMessage>` of twins; rendering checks both. Reason: the
   same uuid carries different information on each stream (links and
   structure vs payload), so it is a record, not a union, and the tree
   build stays a pure function of the entry stream. Anton: agreed.
   Phase-4 shape. (Data flow 6.)

7. **Clients are not assumed to want history or trees.** `subscribe`
   gives `AgentState` + live stream; a client fetches history with
   `get-entries {payload: "full"}` afterwards (the no-cursor handoff
   argument is unchanged). `get-entries`/`get-context` take `payload:
"uuids" | "full"`: `"uuids"` returns just uuids / refs with no file
   read (Anton's `--uuids` idea). `SessionSnapshot` is now `{uuids,
entries?, leaf}`, `ContextSlice` `{refs, entries?}`. `SessionTracker
.entries(since, payload)` becomes `uuidsAfter(since)` + `payloads`.
   (Wire; Data flow 4, 6; Examples.) `tail` and `prompt` are the
   in-tree examples of clients that subscribe but want neither full
   history nor trees.

8. **Steered prompts.** The file records a dequeued steer as
   `attachment {type: "queued_command", prompt, source_uuid}` after the
   tool result it rode on (docs/derisk/uuid-stamping/). It is a
   session-only entry, so it arrives intact; the display tree renders
   it as a user-message row keyed by the attachment's own uuid (a valid
   rewind target), the same code path live and from history. Anton
   first proposed relinking the queued user message under the tool
   result as `USER@TOOL_RESULT` (display-only ref, picker special
   case); the capture shows the tool-result entry carries nothing of
   the steer and the attachment carries `prompt` + `source_uuid`, so
   the attachment itself is the node and no relink is needed. Anton:
   agreed. Caveat recorded in Examples: an attachment in a preserved
   list "contributed nothing" (compact-boundary FINDINGS P3 m6), so a
   rewind to the row likely drops the steer text from context. Phase-4
   work in `DisplayTreeBuilder`. (Criterion 7; Examples.)

9. **Classification fix** (the finding that stopped step 1).
   `/compact`'s "Compacted" is logged as a non-`isMeta` `user` entry
   with string content `<local-command-stdout>…` — and the query
   stream replays it as a `user` message with `isReplay: true` (2/2
   captures: docs/derisk/stream-classification/captures/ and
   /tmp/clauctl-cbi-derisk/stream-classification/). Corpus over 349
   files: stdout entries are never `isMeta` (4519/4519),
   `<command-name>` never (4589), caveat almost always (4591/4596). The
   old table row lumped caveat and stdout as "isMeta, session-only";
   that was wrong for stdout. Now: stdout row = shared (twin: query
   `user` `isReplay`); caveat/`<command-name>` row = session-only.
   `excludedFromQuery(user)` = not(`tool_result` block ∨
   `isCompactSummary` ∨ string content starting with
   `<local-command-stdout>`). `src/format/sdk-message.ts` 170–173
   already drops `isReplay` user messages for display, which is why
   nobody noticed. docs/derisk/stream-classification/README.md line
   ~15–27 says "3/3 shared"; it miscounted — fix when you touch it.
   Under the new design a wrong row also costs bytes (intact instead of
   structural) or loses a payload, so the test in
   tests/sdk/stream-classification.test.ts matters more than before.

10. **`sessionEntry.expectsSdkMessage: boolean`.** The tracker classifies the
    complete entry once (`excludedFromQuery`, its only caller) and the
    fold reads `event.expectsSdkMessage` for `excludeFrom(["query"])`. Reason: the
    stdout rule of decision 9 reads `message.content`, a payload leaf
    the structural projection empties, so a subscriber given the wire
    shape cannot reclassify a shared entry; a flag is the honest
    signal. (Agent events; Agent state; fold rules; criterion 3.)
    Anton: agreed.

## Implementation-Time Decisions

- **`excludedFromQuery` lands in 1b, not step 1.** The tracker needs it
  to set `expectsSdkMessage`, and a throwing stub would fail the tracer. Step 1
  keeps `excludedFromSession` and the capture-pinned test for both.
  Shape: `assistant` → shared; `user` → shared iff `tool_result`
  block ∨ `isCompactSummary` ∨ `<local-command-stdout>` string content;
  `system` → shared iff `compact_boundary`/`local_command`; every other
  type (attachment, uuid-less rows, unknown) → session-only, the safe
  direction the table names. Uuid-less entries get `shared: false`
  without asking (they go out intact and enter no merge).
- **Builder `byUuid` pruning is step 3, not 1b.** The tracker has no
  builders until step 3, so there is nothing to prune yet. Flag for
  step 3: `ContextTreeBuilder.place` reads the _parent's_ entry after
  the parent was consumed (`entryOf(parent).subtype === "compact_boundary"`
  and `byUuid.has(entry.parentUuid)` for tool results); once entries
  are pruned those lookups need a builder-owned record (boundary node
  ids; node existence via `parentMap.has`/the full tree) — a phase-1
  builder change of the same kind as `assistantUsage`. Not done here
  because it is only observable once pruning exists.
- **`assistantUsage` is keyed by uuid, set at every placement** (a
  relinked occurrence re-sets the same value) — one record per
  assistant, not per occurrence, so `lastAssistantOn` over a relinked
  path finds it.
- **`attachment.**` empties `attachment.type` too.** Kept as the spec
  lists it: attachments are a session-only class and never projected on
  the wire, so the only consumer is `structural-stats.ts`.
- **`structural-stats.ts` kept rather than deleted**: the "residue by
  field" table is how a new bulk carrier would be found for
  `PAYLOAD_PATHS`; adapting it cost less than a later rewrite.
