I want to push on my component philosophy from muninn work, where there's a hierarchical dhall/yml/json config for the app as a whole that includes configs for all its components. Those configs can include keyboard shortcuts, rendering/styling info (including color theme), whether to include subcomponents, etc. The idea is that the TUI should do its background work, passing data and configs to its components as data (including keystrokes) arrives. For example, when the user hits a keystroke, its the main app's job to either handle it or direct it to the appropriate sub-component(s).

Some benefits of this are that every component can be written as a little app, so making something like an interactive tree viewer that's separate from the embedded /tree view is easy. Making a non-interactive tree formatter that uses the user's display preferences is also totally straightforward. Something like dhall-lang can be used to allow for flexible composition of configs, allowing things like changing a keyboard shortcut to propagate to all similar components, while still giving the user the ability to customize the shortcut per component. Another benefit is that by componentizing in this way, apps on different platforms should become easier--ideally making a first-pass web or phone version of a terminal app should amount to porting the core event loop (which is generic) and each of the components. Since this is a fundamentally message-passing structure, the components could even be running on different machines.

In rust, I did this by having a single UI thread with a single event loop. Every event (incoming data or user inteaction) was routed through that and down to whatever was supposed to handle them. Whenever any component had to do anything async that would affect the ui thread, it would do it by spawning a separate task which would send the event through a channel. The other end of that channel was given to its parent at construction time, which merged all such subcomponent side-channels together and passed it further up the chain. See ~/git/muninn/.control/concepts/by-name/component-trait-communication-pattern.md, commit cf40fda424 in muninn, and my work on the anton/tui_theme branch.
