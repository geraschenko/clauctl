New in 2.1.250 — need triage

prompt-echo-markdown decided: match

2.1.250 reverses claude's own 2.1.211 behavior: the user prompt echo is now markdown-rendered — **bold**, *italic*, and backticked code have their markers consumed and styling applied, which also changes the wrap points. clauctl echoes the prompt verbatim, which was the decided "user-verbatim: match" behavior from the 2026-07 catalog — i.e. clauctl still does what claude used to do. Following the same "render like claude" principle would flip clauctl back to rendering the echo (its pre-parity behavior); the counterargument is that a verbatim echo shows exactly what the user typed. Decision needed; affects three scenarios and every quoted-code prompt in real sessions.

parallel-tool-fork open: loader investigation required

Found by the readonly-fold scenario (2026-08-28): when one assistant message issues parallel tool calls and results arrive out of order, the CLI records a fork — here Glob's tool_use parents onto the Grep tool_use entry, Glob's result onto Glob, but Grep's later result also parents onto the Grep entry, and the conversation continues from Grep's result. clauctl's replay (pathToLeaf, the /tree path semantics used by both the attach TUI replay and the direct render) walks the linear parent chain and drops the whole Glob branch — call and result vanish; the fold's summed thinking duration shifts too (8s vs claude's 25s). Native claude renders every entry. The live clauctl TUI is unaffected (it appends streamed messages). Not a style diff: a design decision about replay path semantics vs in-turn forks. Decision (2026-08-28): the fork implies claude's context loader cannot be the assumed walk-parentUuid-from-last-entry (docs/derisk/compact-boundary-injection/ FINDINGS.md) — it must reach the off-path Glob branch somehow. Investigated (2026-08-28, live experiments):

  • The SDK's getSessionMessages returns all four calls+results in file order, Glob branch included.
  • Control: a session copy with a synthetic rewind fork (an abandoned user branch as leaf) returned only the root→leaf path — so it does walk parents and drops abandoned branches; it is not a file dump.
  • Live loader agrees: claude --resume of a session copy, asked to enumerate its context, listed all 4 tool calls and results.
  • Structural rule consistent with all three: path walk from leaf, expanded with assistant entries sharing a message.id with an on-path entry (the CLI splits one API message into several entries; parallel tool_uses land as same-id siblings — Glob's entry shares msg_011CeVfZ5CLZ… with the on-path Grep entries) plus the tool_results of every included tool_use. Rewind forks fork at different API messages, so they stay excluded.
  • Also attested by the regenerated tools scenario (Write+Read and Bash+Bash parallel pairs, one result each off-path) — the pattern is common, not exotic.

Remaining decision: adopt this rule in clauctl's replay (pathToLeaf consumers: attach TUI, direct render) and correct compact-boundary-injection FINDINGS.md / loadedContext accordingly.

grep-glob-fold-label decided: differ (keep separate clauses)

Attested: claude's fold counts Grep and Glob together as searched for N patterns (2 patterns = 1 Grep + 1 Glob above; the 2026-07 catalog saw the same phrasing for Bash find commands). clauctl's generic clause says used Grep 1 time. Decision (2026-08-28): keep Grep and Glob as separate per-tool clauses rather than merging their counts.

websearch-visible decided: match (WebSearch not read-only)

Attested: claude does NOT fold WebSearch — it renders a visible tool line with display name "Web Search", the query as header arg, and a duration summary; folds break around it. clauctl folds it via READ_ONLY_TOOLS (used WebSearch 1 time). Decision (2026-08-28): WebSearch is not read-only — a network operation heavy enough to stay visible. Removed from the shared READ_ONLY_TOOLS set (so neither the TUI fold nor the formatter's coalescing absorbs it) and given a bespoke view (websearch.ts) matching claude's rendering.
